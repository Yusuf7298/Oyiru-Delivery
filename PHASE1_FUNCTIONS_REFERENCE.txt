CORE ORDER FUNCTIONS
================================================================================

1. createProductOrder()
   Location: /app/actions/product-orders.ts
   Purpose: Create a new product order
   
   Input:
   {
     items: Array<{productId, name, price, quantity}>
     totalAmount: number
     deliveryAddress: string
     deliveryCity: string
     customerPhoneNumber?: string
     specialInstructions?: string
   }
   
   Output:
   {
     success: boolean
     orderId: string
     message: string
   }
   
   What it does:
   - Validates user is authenticated
   - Creates transaction (BEGIN)
   - Inserts order into product_orders table
   - For each item:
     * Inserts into product_order_items table
     * Reduces product inventory
   - Commits transaction (COMMIT)
   - Returns orderId for confirmation page
   
   Used By:
   - /app/checkout/page.tsx
   - /app/api/test-order/route.ts
   - Flow 1: Customer Orders
   - Flow 2: Hotel Bulk Orders
   - Flow 5: Telegram Bot Orders

================================================================================

8. reduceInventory() [Inline in createProductOrder]
   Location: /app/actions/product-orders.ts (line 92-95)
   Purpose: Decrease product stock quantity
   
   Input:
   {
     productId: string
     quantity: number
   }

================================================================================

TRANSACTION SUPPORT
================================================================================

All order creation is wrapped in DATABASE TRANSACTIONS:

BEGIN TRANSACTION
  ├─ CREATE order in product_orders
  ├─ FOR EACH item:
  │  ├─ CREATE order_item in product_order_items
  │  └─ UPDATE product stockQuantity
  └─ COMMIT

If ANY step fails: ROLLBACK (undo all changes)

Benefits:
✓ Prevents partial orders
✓ Prevents double-deduction
✓ Data consistency guaranteed
✓ Atomic operations

ERROR HANDLING
================================================================================

All functions include error handling:

Function: createProductOrder()
Errors:
  - "User must be authenticated" → redirect to /sign-in
  - "Order must contain at least one item" → show validation error
  - Database errors → ROLLBACK transaction, show error message

Function: getUserId()
Error:
  - "Not authenticated" → throws error (caller handles redirect)

Function: getSession()
Error:
  - Returns null if session expired/invalid → caller redirects

Function: updateOrderStatus()
Error:
  - "Order not found" → show error
  - "Invalid status" → show error

FLOWS USING THESE FUNCTIONS
================================================================================

FLOW 1: Customer Order (✅ PASS)
  1. Customer views products
  2. Adds items to cart (useCart context)
  3. Clicks "Proceed to Checkout"
  4. getSession() verifies auth
  5. Fills delivery form
  6. Clicks "Place Order"
  7. createProductOrder() executes
  8. clearCart() clears items
  9. Order confirmation page displays getOrderById()

FLOW 2: Hotel Bulk Order (⚠️ READY)
  1. Hotel staff logs in
  2. Selects products and quantities
  3. Submits order
  4. createProductOrder() executes (with hotel context)
  5. Order appears in admin dashboard

FLOW 3: Driver Assignment (✅ READY)
  1. Driver sees orders via getCustomerOrders() endpoint
  2. Driver accepts order
  3. updateOrderStatus() to 'processing'
  4. Driver tracks delivery

FLOW 4: Admin Management (✅ PASS)
  1. Admin views all orders
  2. getCustomerOrders() or query all
  3. getOrderById() for details
  4. updateOrderStatus() to approve/reject

FLOW 5: Telegram Bot (✅ READY)
  1. User sends /place-order command
  2. Bot calls createProductOrder() via API
  3. Bot confirms with orderId
  4. Bot links to order-confirmation page
